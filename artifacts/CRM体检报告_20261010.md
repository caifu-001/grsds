## 一、总体评价

| 维度 | 评价 |
|---|---|
| 功能覆盖 | ⭐⭐⭐⭐ 很宽。客户/联系人/线索公海/商机/46步项目工作台（含会签审批、借壳分支）/订单/报价/合同/回款/售后/供应链/供应商/采购/选品/协同/外勤/多套报表/组织权限/系统配置，覆盖面接近中大型 B2B 项目型 CRM |

| UI 一致性 | ⭐⭐ 变量缺失导致大面积样式静默失效；三套主色并存 |

**核心结论**：功能建得很多，但**安全闸门缺失**、**部分模块是空壳**、**样式底座有系统性缺陷**。建议按下方路线图分三批修复。

## 二、P0-1 安全问题（最紧急，建议今天就处理）

### 🔴 A. `admin-proxy` 接口完全无鉴权 → 任何人可读写全库、重置任意密码、删除用户

**证据**

`supabase/config.toml:262-264`
```toml
[functions.admin-proxy]
enabled = true
verify_jwt = false        # ← 平台层 JWT 强制校验被关闭
```

`supabase/functions/admin-proxy/index.ts:29-47` —— 全文检索 `getUser|role|401|403` **均无命中**，函数拿到 service_role key 后直接执行请求体指定的任意操作：
```ts
const SUPABASE_SERVICE_KEY = Deno.env.get("SUPABASE_SERVICE_ROLE_KEY") || "";
const { op, table, payload, query, filters, userId, password } = body;  // 只信任请求体，不校验调用者
```
`index.ts:9` CORS 为 `Access-Control-Allow-Origin: *`；`index.ts:84-97` 支持 `auth_reset_password`；`index.ts:99-123` 支持 `auth_delete_user`；`index.ts:141-225` 支持对**任意表**增删改查。

**影响**：任何知道该 URL 的人（**甚至无需登录**）POST 一个请求即可：
- 读取**所有公司**的全部客户、联系人、金额数据
- 重置**任意账号**（含超管）的密码 → 账户接管
- 删除任意用户

**修复**（3 步）
1. `config.toml` 改 `verify_jwt = true`
2. 函数内解析 `Authorization` 头的用户 token，查 `company_memberships` 判定是否 `admin/super_admin`，非管理员直接返回 403
3. `update/delete` 强制拼装全部 filters 并注入 `company_id`，禁止无条件全表操作；CORS 收敛到 `https://caifu-001.github.io`

### 🔴 B. 资源授权只在前端过滤（数据早已被拉到浏览器）

`js/app_v2.js:757-772`（注释自曝）
```js
// 非管理员用 callAdmin 绕过 RLS，再前端 canAccess 过滤
var r=await callAdmin('select','clients',{...,filters:[{col:'',op:'limit',val:'50000'}]});
allClients=allClients.filter(function(cl){return canAccess('clients',cl.id);});
```
同样的模式出现在产品 `:5944-5953`、供应商 `:7342-7350`。

**影响**：非管理员在浏览器控制台直接调 `callAdmin('select','clients',...)` 即可拿到**未授权客户**的完整数据（含联系人、金额）。前端 `canAccess()` 形同虚设。

**修复**：把资源授权下沉到 RLS policy，或让 Edge Function 依据调用者 token 在服务端过滤。

### 🔴 C. 角色/管理权限只靠「隐藏按钮」

`js/app_v2.js:233-234`、`:3617-3623`、`:4023`、`:4090`、`:4290` —— 是否显示管理员入口仅靠 `classList.add('hidden')`；而真正的写操作直通 A 的代理接口。

**影响**：普通成员在控制台调用 `setUserRole()` / `deleteUser()` / `resetPassword()` 即可**自我提权、删除同事、重置管理员密码**。

### 🟠 D. 存储型 XSS（未转义的 innerHTML 拼接）

| 位置 | 未转义字段 | 证据 |
|---|---|---|
| `app_v2.js:7442-7444` | 供应商产品清单 `pr.name` / `pr.moq` | 同函数其他字段都用了 `escHtml`，唯独此处漏掉 |
| `app_v2.js:686-689`、`:698-701` | 自定义客户类型标签 | `:465` 同类场景已用 `h()`，属遗漏 |
| `app_v2.js:5083` | 知识库标签 `k.tags` | 同函数其他字段已转义 |
| `app_v2.js:8551`、`:8587` | 用户 `display_name`（可广播给所有用户） | 下拉选项未转义 |
| `app_v2.js:643`、`:10371`、`:13105`、`:13449`、`:13761-13790` | 公司名 / 流程分支 / 签到地址 / 地图 InfoWindow / 工作流字段 | — |

**修复**：统一补 `h()`。同时建议**删除重复的转义函数**：`h()`（`:72`）与 `escHtml()`（`:4208`）逻辑完全相同，`escAttr()`（`:2852`）的单引号转义是空操作（`"\'"` 就是 `'`）。

> ⚠️ 特别提醒：`var h=''` 被 **49 个函数**当作 HTML 累加器使用，会**遮蔽全局 `h()` 转义函数**。目前这些函数恰好用 `escHtml` 才没出事，但后续谁在里面写 `h(x)` 都会直接报错。

### 🟠 E. `admin-proxy` 的 update/delete 只用第一个 filter

`index.ts:166-190`：`var f0 = filters[0]` —— 多条件过滤被丢弃；若 filters 为空则退化为**全表更新/删除**。

### 🟠 F. 金额「加密」使用硬编码客户端密钥

`app_v2.js:1659-1667`：密钥 = `user_id + '-crm-order-key-2026'`，盐固定 `'order-amount-salt'`。user_id 是公开的 → 任何拿到密文的人都能离线派生密钥解密。**不具备实际机密性**。

## 四、P1 UI 界面问题

### 🔴 U1. 10 个 CSS 变量被引用但从未定义 → 大面积样式静默失效

`:root`（`app.css:2-23`）未定义这些变量，但被大量引用（**已核验计数**）：

| 变量 | CSS 引用 | HTML 内联引用 | 后果 |
|---|---|---|---|
| `--card-bg` | 21 | **67** | 卡片背景退化为 `transparent`，与页面融为一体 |
| `--text-secondary` | 25 | 6 | 次要文字颜色失效 |
| `--bg2` | 7 | 13 | — |
| `--muted` | 0 | 4 | — |
| `--hover` / `--border2` / `--primary-soft` / `--accent` | 各 1 | 各 0-1 | — |

**典型受害组件**：`.dash-card`（`app.css:694`）、`.report-chart`（`:728`）、`.wb-phase-header`（`:952`）、`.project-card`，以及项目工作台几乎**所有输入框和卡片**（`index.html:1543`、`:1742` 等 67 处内联 `var(--card-bg)`）。

> 这是本次审计中**性价比最高的一个修复**：在 `:root` 补齐 10 个变量，可一次性修复大片透明/失色。

### 🔴 U2. `.toast` 被定义两次 → 提示重叠且背景透明

```css
app.css:178 .toast{position:fixed;top:72px;left:50%;transform:translateX(-50%);background:rgba(15,23,42,.88);...}
app.css:780 .toast{background:var(--card-bg);border-left:4px solid #4F6EF7;...}   /* 后者生效，但 --card-bg 未定义 → 透明 */
```
JS 把 toast 追加进 `#toast-container`（`app.css:779`，flex 纵排），但 `.toast` 自身是 `position:fixed;top:72px;left:50%`，**脱离容器流** → 所有提示堆叠在同一位置、且背景透明（深色界面上几乎不可读）。退出动画 `translateX(40px)`（`:782`）与初始 `translateX(-50%)` 冲突会跳变。

### 🔴 U3. 全站禁止文本选择

`app.css:24` `body{...user-select:none;...}` —— 订单号、客户电话、地址、金额**都无法选中复制**，对 B 端录入/核对场景是硬伤。

### 🟠 U4. 禁用页面缩放

`index.html:5` `maximum-scale=1.0,user-scalable=no` —— 低视力用户无法放大（WCAG 1.4.4 违规）。

### 🟠 U5. 桌面端是「被拉满的移动端布局」

`app.css:80` `.client-grid{grid-template-columns:1fr;...}` —— 全文只有这一处，**没有任何桌面多列规则**。配合 `app.css:25` 桌面 `body{max-width:100%}`，客户/订单/报价卡片在 1920px 屏上**单列铺满整行**，极度浪费横向空间。而 481-768px 又被强制压成 480px 居中窄条（中间断点缺失）。

### 🟠 U6. 主色不统一：一个系统三种蓝

| 色值 | 出现次数 | 说明 |
|---|---|---|
| `#6366F1` | 14 | `--primary`（当前主色） |

`app.css` 中硬编码 hex 共 **326 处**，未归一到变量。

### 🟠 U7. 字号普遍过小

- `9px`：`.wb-step-num`（`app.css:963`）、`.pd-dept-tag`（`:1188`）
- `10px`：`.card-type`（`:87`）、`.os-label`（`:284`）、`.notif-time`（`:768`）

9-11px 在移动端基本不可读，建议正文 ≥14px、次要信息 ≥12px。

### 🟠 U8. z-index 体系混乱

层级值横跨 `1 → 99999`（20+ 档）。关键冲突：通知面板（`:757`）与成员面板（`index.html:132`）都是 `z-index:10000`，而通用弹窗 `.modal-overlay` 只有 `z-index:300` → **面板开着时打开弹窗会被盖住**。

另有 `.toolbar`（`:63`）与 `.biz-tabs`（`:245`）都 `sticky;top:48px`，前者 `z-index:99` 会压住后者 `98` —— 部分页面已用内联 `style="position:static"` 打特例补丁，说明是已知问题。

### 🟠 U9. 触摸目标偏小（<44px）

`.contact-item .del-btn` 26px（`:128`）、`.modal-close` 32px（`:113`）、`.qi-del`/`.pe-remove` 24px（`:451`/`:682`）、`.btn-xs` `padding:2px 8px`（`index.html:1008`）。且 **`.btn-xs` 在 app.css 中根本没有定义**。

### 🟠 U10. 键盘完全不可达 + 零无障碍标注

全站可点击卡片都是 `<div onclick>`（如客户卡 `app_v2.js:990`、订单卡 `:3284`），非 `button`、无 `role`、无 `tabindex` → **主要功能入口无法用键盘操作**。

`aria-label` / `role=` / `alt=` / `tabindex` 在 `index.html`（2742 行）与 `app_v2.js` 中**出现次数均为 0**。

### 🟡 U11. 其它

- 无骨架屏（`skeleton` 出现 0 次），加载态仅转圈或「加载中...」文本（17 处）
- 「冻结」死按钮被复制进 9+ 个无关弹窗（`index.html:793`、`2363`、`2395`、`2443`…），点击只弹「冻结功能暂未开放」

- `--text3:#94A3B8` 白底对比度约 2.6:1，低于 WCAG AA
